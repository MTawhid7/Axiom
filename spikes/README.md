# Spikes (Phase Zero)

This directory holds validation experiments. The code is **throwaway and not production**: it exists to answer the questions in a step's plan, and its results live in `docs/research/`.
- S1 and S2 validate [ADR-0002](../docs/adr/0002-implementation-language.md) ([Step 2b plan](../docs/research/step-2b-validation-spikes.md)).
- S4 validates [ADR-0004](../docs/adr/0004-process-model-and-sandbox.md) ([Step 3 plan](../docs/research/step-3-security-and-process-model.md); design in the [macOS confinement note](../docs/research/macos-process-confinement.md) §7).
- S3 validates ADR-0003's obligation C1 for [ADR-0008](../docs/adr/0008-script-agents-and-heap.md), and measures dispatch, layout and barriers ([Step 4 plan](../docs/research/step-4-architecture-proposal.md) §10).
- S5 tests the text stack for [ADR-0011](../docs/adr/0011-text-fonts-and-unicode.md), and ImageIO in the renderer's sandbox for [ADR-0012](../docs/adr/0012-graphics-images-and-media.md) ([Step 5 plan](../docs/research/step-5-subsystems.md) §10.1).
- S6 measures compositing on Metal for [ADR-0012](../docs/adr/0012-graphics-images-and-media.md) ([Step 5 plan](../docs/research/step-5-subsystems.md) §10.2).
- S7 validates the network process's sandbox and TLS for [ADR-0013](../docs/adr/0013-networking-storage-and-workers.md) ([Step 5 plan](../docs/research/step-5-subsystems.md) §10.3).
- S8 is the corpus census for Step 6 ([Step 6 plan](../docs/research/step-6-standards-budgets-roadmap.md) §10.1; [corpus](../docs/corpus.md)). It is Python, with the standard library only, outside the Cargo workspace.
- S9 tries the test tools on this Mac for the [testing strategy](../docs/testing.md) §9: cargo-fuzz with AddressSanitizer and coverage, ThreadSanitizer, and wptrunner ([results](../docs/research/s9-results.md)).
- S10, S12 and S15 serve the architecture review's Round 1, authorized by the owner on 2026-10-21 ([the review](../docs/review/README.md) §5.2). S10 measures the GPU/compositor process the review adds: its hop to the browser, zero-copy resources and display-list validation ([results](../docs/research/s10-results.md)). S12 finds a ThreadSanitizer route on macOS 27, reusing S9's `race` crate ([results](../docs/research/s12-results.md)). S15 tests a stable local signing identity ([results](../docs/research/s15-results.md)).
- S16 serves the review's Round 4, authorized by the owner on 2026-10-22 ([the review](../docs/review/README.md) §5.8): what happens to shared memory and port rights when a process dies or a message is dropped, and whether rusage's counters can check efficiency at every checkpoint ([results](../docs/research/s16-results.md)).

## Rules

- **Each results document records the macOS build** (`sw_vers`'s `BuildVersion`) its measurements ran on, beside its other conditions, and notes when its checks were last confirmed on a newer build (TS16; Round 4, RV4-13).

- **The unsafe-code policy applies to spikes too** (evaluation §15.3; `tools/check-unsafe-policy.sh`).
  - Every crate root declares `#![forbid(unsafe_code)]`, except crates listed in `tools/unsafe-policy.txt`.
  - Listed crates declare `#![deny(unsafe_code)]`, and allow `unsafe` only in their listed modules.
- **The spikes are a workspace of their own** since Milestone 1's second checkpoint (2026-10-23; ADR-0022 D12): `spikes/Cargo.toml`, with the lock they were built with, `spikes/Cargo.lock`, and the lints and Clippy settings they were written under (`spikes/clippy.toml`). The engine's workspace is the repository's root. Run a spike's cargo commands from `spikes/`, or from the root with `--manifest-path spikes/Cargo.toml`; the commands below are written for the spikes' workspace. Both workspaces build into the repository's `target/` (`.cargo/config.toml`), so the paths below, such as `target/release/s3-probe`, are unchanged, and the measurement scripts pass the manifest themselves.
- **Verification before every commit** covers both workspaces, through `tools/check.sh` from M1-CP2. For the spikes alone:

  ```sh
  cargo fmt --manifest-path spikes/Cargo.toml --all --check
  cargo clippy --manifest-path spikes/Cargo.toml --workspace --all-targets -- -D warnings
  cargo test --manifest-path spikes/Cargo.toml --workspace
  tools/check-unsafe-policy.sh
  tools/check-doc-links.py   # every relative Markdown link and anchor resolves
  ```

- **Build measurements:** `tools/measure-build.sh --help`.
- **Runtime measurements** (CP7 and CP8). Each script prints its usage with `--help`, and writes its results under `target/s1-results/` or `target/s2-results/`.

  `cargo bench -p s1-bench` runs one pass of the S1 runtime suites. `cargo run -p s2-window -- --smoke` checks the S2 window's rendering (it opens a window briefly).
- **S3.** `cargo test -p s3-gc -p s3-vm -p s3-bench` runs the heap and root-stack tests, the interpreter's oracle (every technique on every stack, at normal pacing and when collecting at every allocation) and a quick pass of every benchmark suite. Add `--features count` for the check that bytecode never roots. C1's stack, `SliceStack`, has no `unsafe`; Miri covers the archived `RawStack`'s: `cargo +nightly miri test -p s3-gc`, and `cargo +nightly miri test -p s3-vm --test miri`. `target/release/s3-probe roots` prints the root stacks' unit costs, and `/usr/bin/time -l target/release/s3-probe footprint slice 1000` shows what a stack commits.
- **S4.** `cargo test -p s4-sandbox` runs the sandbox probes against the linker-signed helper. `tools/s4-sign.sh` signs copies ad hoc with the hardened runtime (plus the JIT variants), and `target/s4/bin/s4-broker probe|startup|ipc|jit|text` runs each scenario against them. `tools/s4-measure.sh` runs them all on release builds and writes `target/s4-results/<timestamp>/`. `--named-profile`, and `cargo test -p s4-sandbox -- --ignored`, also check that a named profile kills the helper; each such run leaves a crash report in `~/Library/Logs/DiagnosticReports`.
- **S5.** `cargo test -p s5-rust-text -p s5-text -p s5-image` runs the container, shaping, tracking, rasterizer and decoder tests, and a Latin line against CoreText. `tools/s5-fetch.sh` and `tools/s5-images.sh` prepare the inputs in `target/s5/`. Then `target/release/s5-text shape|raster|speed|footprint`, `target/release/s5-webfont check FILE...` and `target/release/s5-image decode|compare` run each question by hand, and `tools/s5-measure.sh` runs them all and writes `target/s5-results/<timestamp>/`. Its `--crash-checks` runs what is expected to crash, and moves the crash reports into the results. **Re-run on macOS 26B118** (2026-10-22; Round 4, RV4-13): `target/s5-results/20261022-182712/`, compared in its results' §12.
- **S6.** `cargo test -p s6-compositor` runs the tiling, text, scene, path and counter tests. `target/release/s6-compositor q1|q2|q3|q5` opens a 1,280 × 800-point window at the top left of the screen (it can't appear over another app in full screen); `q4` runs offscreen. `tools/s6-measure.sh` runs them all and writes `target/s6-results/<timestamp>/`; its formal runs need AC power, the Mac otherwise idle, and the window visible, which each run records. `python3 -I tools/s6-tails.py target/s6-results/<timestamp>` counts the frames over each threshold, and `tools/png-region-stats.py` reads a screenshot of the colour pattern (`q5 --show`). **Re-run on macOS 26B118** (2026-10-22; Round 4, RV4-13): `target/s6-results/20261022-183751/`, compared in its results' §11.
- **S7.** `cargo test -p s7-net` runs the HTTP/1.1 framing, QPACK and varint, kqueue (sockets, timers, user events and Mach messages from one wait), socket, counter and record-parsing tests, offline. `target/release/s7-net MODE` is the broker: it compiles `spikes/s7/net/profiles/network.sb` and launches itself as the sandboxed helper (`--profile none` runs it unsandboxed); the modes are `verify`, `probe`, `handshakes`, `download`, `dns`, `one-wait` and `ready`, and every mode but `ready` and `probe` contacts public hosts. `tools/s7-measure.sh` runs them all and writes `target/s7-results/<timestamp>/`. **Re-run on macOS 26B118** (2026-10-22; Round 4, RV4-13): `target/s7-results/20261022-185224/`, compared in its results' §12.
- **S8.** `python3 -I spikes/s8/test_s8.py` runs its offline tests: robots matching, `top`'s output, the use-counter enums, the corpus list. `python3 -I spikes/s8/s8.py check` runs one census of a local test page served on 127.0.0.1, and `s8.py robots` prints each automated page's robots.txt verdict. `tools/s8-measure.sh` runs the automated census and writes `target/s8-results/<timestamp>-auto/`. `s8.py signin` opens Chrome Canary's dedicated profile in `scratch/s8/`, for the owner to sign in by hand; `s8.py hand --browser chrome|safari --mode logged-out|signed-in` runs the census by hand, prompting each step, and samples only the browser's processes. Each run by hand records its own baseline on the list page, and Safari is restarted for each page. `s8.py blank` measures a fresh Canary on about:blank: the baseline for the session of 2026-10-20, which recorded none. It never opens the dedicated profile (corpus CO14). Every automated load carries `AxiomCensus/0.1` in its user agent (corpus CO4).
- **S9.** `cargo test -p s9-decoder -p s9-race` runs the decoder's tests and the atomic counter's; the racy test is ignored outside ThreadSanitizer. `tools/s9-measure.sh setup fuzz coverage tsan wpt-setup wpt` runs every question and writes `target/s9-results/<timestamp>/`; `fuzz` runs each target for `--seconds` (default 600), and `wpt` runs `--wpt-dir` (default `dom/nodes`) against Chrome Canary. The fuzz crate builds only through cargo-fuzz, on nightly.
- **S10.** `cargo test -p s10-gpu` runs the display-list round-trip, refusal and statistics tests. `target/release/s10 hop|resources|validate` runs each question by hand: the browser launches itself as the GPU process and the renderer, each under its profile from `spikes/s10/gpu/profiles/` (`--gpu-profile` and `--renderer-profile` choose others: `none`, `report`, or `file:PATH`), with no window. `S10_SHADER_NONCE=X` forces a cold shader compile. `tools/s10-measure.sh` runs them all on a signed copy and writes `target/s10-results/<timestamp>/`; its formal runs need AC power.
- **S12.** `rustup toolchain install nightly-2026-10-21 --profile minimal --component rust-src`, then `tools/s12-measure.sh bundled external baseline` runs the race tests by each route and writes `target/s12-results/<timestamp>/`. `baseline` reproduces S9's crash, and moves its crash report into the results.
- **S15.** `cargo test -p s15-probe` builds the probe. `tools/s15-measure.sh setup s4 keychain requirement teardown` makes a throwaway keychain with a self-signed identity under `target/s15/`, runs every question, deletes the keychain and its key, and writes `target/s15-results/<timestamp>/`. `tools/s4-sign.sh --identity SHA1 --keychain PATH` signs S4's binaries with any identity. The login keychain and trust settings are never touched.
- **S16.** `cargo build -p s16-lifetime --release` builds it; it has no unit tests, since each question is a run between processes. `target/release/s16 memory|surfaces|rights|counters` runs each question by hand: the browser launches itself as the renderer and the GPU process under S10's profiles (`memory --compositor browser|gpu --end kill|exit [--cpu-touch]`). `tools/s16-measure.sh` runs them all on a signed copy and writes `target/s16-results/<timestamp>/`; its formal runs need AC power and wait for the load to fall below 3.0, and `--quick` makes one short pass.
