# ADR-NNNN: Title

| | |
|---|---|
| **Status** | Proposed / Accepted / Rejected / Superseded by ADR-XXXX |
| **Date** | YYYY-MM-DD |
| **Deciders** | Project owner (only the owner can move an ADR to Accepted) |
| **Related** | Links to the charter, other ADRs, research notes |

## Question

What exactly is being decided, in one or two sentences.

## Requirements and constraints

The requirements, accepted decisions and environment facts that bear on this question, with links.

## Alternatives considered

A small number of meaningful alternatives, each described in a short paragraph.

## Historical context and modern developments

Why existing systems made the choices they did. Which of their constraints still apply to us and which are obsolete. Mark each claim as a sourced fact, an inference or a hypothesis.

## Analysis

For each alternative:
- advantages and disadvantages;
- implications for performance, security, complexity and maintenance.

## Evidence and sources

Primary sources wherever practical. Label secondary sources as secondary.

## Decision

The decision if Accepted, or the recommendation if Proposed.

## Rationale

Why this alternative, tied to specific requirements.

## Assumptions

What must be true for this decision to remain correct.

## Risks and unresolved issues

Each risk with its likelihood, impact and mitigation.

## Conditions for revisiting

Concrete, observable conditions that would reopen this decision.

## Consequences

What this decision forces, enables or rules out elsewhere in the architecture.
