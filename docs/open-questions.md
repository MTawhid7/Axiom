| OQ-4 | JIT policy: if and when to add a baseline JIT, and when to disable JIT (sensitive sites)? | The JIT is the highest-risk attack surface; it determines performance on app-web sites | Isolation and sandbox design (Step 3); interpreter performance data | Step 3 (policy); much later (implementation) | **Policy resolved 2026-10-17:** the owner accepted [ADR-0004](adr/0004-process-model-and-sandbox.md) D7 (rules J1–J7), with global and per-site switches: no JIT before security level L2; only the `renderer-jit` executable may create executable memory; sensitive sites always run without a JIT; a global switch. *Whether* to build a JIT stays evidence-driven: spike S3 in Step 4, and corpus measurements once OQ-2 is answered |
| OQ-5 | Per-agent heaps: how are workers, `SharedArrayBuffer` and cross-agent messaging represented in the GC design? | Affects GC architecture and the process model | S1 results; Step 4 design | Step 4 | Open. **Step 3 input** (proposed, [process model](security/process-model.md) SI7): one agent cluster per process; dedicated workers share their document's process; shared and service workers run in a renderer locked to their site; cross-origin isolated groups get their own processes |
| OQ-6 | Which languages is the owner fluent in? | Learning cost is a factor in ADR-0002 | Owner input | Before ADR-0002 is accepted | **Resolved 2026-10-16:** the owner is fluent in Rust. Code must not be simplified for learning reasons |
| OQ-7 | When should full Xcode be installed (Instruments, Metal tooling)? | Serious profiling; Metal debugging | Owner preference | Before the first performance-critical milestone | Open. **S2 evidence (2026-10-17):** the Command Line Tools have no offline Metal compiler. | OQ-8 | Version control: initialize a git repository for `docs/` now? | ADR history and diffs; continuity across sessions | Owner authorization | Now (recommended) | **Resolved 2026-10-16:** repository initialized; baseline `a223fe2` on `main`. Step 2b work is on branch `step-2b` |
| OQ-9 | Is the owner the only human developer? | Roadmap, review process, workload | Owner input | Step 6 | Assumed yes |
| OQ-10 | Which GC handle/rooting pattern: gc-arena-style, Nova-style scoped handles, or an unsafe core with a precise shadow stack? | Decides whether `unsafe` stays contained (the key ADR-0002 hypothesis) | Spike S1 | Before ADR-0002 is accepted | **Resolved 2026-10-17:** [ADR-0003](adr/0003-gc-handle-and-rooting-pattern.md) Accepted. | OQ-11 | Platform shell: pure Rust (objc2) or a thin Swift layer? | Ergonomics against the cost of two toolchains | S2; Step 4 | Step 4 | **Leaning pure Rust, supported by S2 (2026-10-17):** objc2 handles the window, Metal and CoreText path with most calls safe and 19 `unsafe` sites, all contained ([S2 results](research/s2-results.md)). Accessibility, IME, menus and app bundles are untested. **Step 3** (proposed): only the browser process uses AppKit; renderers link no AppKit and have no window-server connection |
| OQ-12 | What are the build-time and memory thresholds on the 8 GB M1? | Revisit condition 3 for ADR-0002 | `tools/measure-build.sh` (from CP1); S1 and S2 measurements | Thresholds set in CP8 (evaluation §15.6 assigns them to S2) | **Resolved 2026-10-17:** thresholds T1–T4 accepted as the meaning of ADR-0002 revisit condition 3 ([ADR-0002](adr/0002-implementation-language.md); [S2 results](research/s2-results.md) §6) |
| OQ-13 | Incremental or generational collection, and a write-barrier API, for the chosen GC pattern | S1's Pattern B pauses are stop-the-world: about 4 ms at 130k live nodes and 15 ms at 333k objects. To be settled in Step 4 (ADR-0003 obligations C3, C4) |
| OQ-14 | Root-stack design for Pattern B: can rooting cost at most 1 ns per root and per read? | Rooting dominates B's overhead in code that holds many handles across possible collections: dispatch takes 2.06× A's time. | OQ-15 | Should S3, an interpreter micro-benchmark, become required rather than optional? | It would measure rooting traffic inside an interpreter loop, the main unmeasured input to ADR-0003 | Owner decision | CP9 | **Resolved 2026-10-17:** S3 is a **required** benchmark. It runs during Step 4 as part of the interpreter and root-stack design, and validates ADR-0003 obligation C1 |
| OQ-16 | How can Axiom support WebAuthn and passkeys without a paid developer account? | High-value accounts increasingly use passkeys, and the sensitive-use gate (L3) is for exactly those accounts | **Hypothesis:** the platform authenticator needs a restricted entitlement; Chrome carries `com.apple.developer.web-browser.public-key-credential` (observed).
